# 排查手册

按「你看到的现象」查，不用从头读。

---

## 一、连不上 / 打不开

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `连不上浏览器调试端口 9223` | 专用浏览器没开，或者被关了 | 跑 `python step0_open.py` |
| 端口开了但读不到页面 | 打开的窗口里没有学习通的标签页 | 在那个窗口里打开一次课程页 |
| 一个 cookie 都没拿到 | 还没登录，或登录过期 | 在专用窗口重新登录，再跑 `step4_cookies.py` |
| `登录凭证不全（缺 _uid / fid）` | 同上，或者导出的时机太早 | 登录后进到课程页再导出 |

**判断专用浏览器是不是开着：** 跑 `python 环境自检.py`，看第 4 项。

---

## 二、登记课程失败

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `当前页面地址里没找到课程号` | 当前标签页不是课程页（可能是首页/空间页） | 点进那门课，再运行 |
| `补不到 cpi` | 停在的页面太浅，地址里没带 cpi | 点进**某一章**，让地址栏出现 `cpi=数字` |
| stuenc 是空的 | 有些入口不返回这个参数 | 一般不影响，先往下跑试试 |

**怎么看课程号：** 地址栏里 `courseid=268330787` 这一串数字就是。
`clazzid` 是班级号，`cpi` 也是必须的。

---

## 三、章节扫描不出东西

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `共 0 个章节` | 登录过期，或者课程页还没加载完 | 重新登录；或在浏览器里手动打开一次章节页再跑 |
| 章节有，但每章都是 `[]` | 该章的卡片接口返回了提示页 | 通常是权限/时间问题，手动在网页里点开那一章看看能不能看 |
| 扫到一半报错 | 网络抖动或页面超时 | 直接重跑，已扫过的会重新扫但无害 |

## 四、答题相关

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `no hook` | 注入的脚本没跑起来 | 页面刷新后重跑；仍不行说明脚本本体和当前页面版本不匹配 |
| 一直 `answering` 不动 | AI 接口慢，或密钥额度用完了 | 看 `data/quiz_<课程号>.log`；换个密钥试 |
| `no-answer-abort` | 一道题都没答上，脚本主动放弃提交（保护你不交白卷） | 检查 `config.json` 里的密钥和模型名 |
| 提交了但分数很低 | AI 答错，正常现象 | 重跑那几章（加 `--kid 章节号` 单独跑） |
| `timeout` | 单章超过 240 秒没结果 | 重跑一次；连续出现就把 `--limit` 调小分批做 |

**已经做完的章节会被跳过**（日志里的「已完成，跳过」），所以放心反复跑。

## 五、视频相关（最容易踩的地方）

### 现象：进度显示满了，但一直「未通过」

这是最典型的问题，三个原因按顺序排查：

**原因 1：上报间隔太短。**
服务器要求「至少隔 N 秒报一次」，你报得比它要求的勤，增量会被丢掉。
表现就是位置打满但不给通过。

自查：`step5_jobs.py` 最后会打印「服务器要求的上报间隔：N 秒」。
跑 `step6_video.py` 时不要手动把 `--gap` 调得比它小。

**原因 2：跑太快被临时限速。**
连续高速刷了几个小时后，服务器会临时降低给你的额度（不是封号）。
表现：前面几个都过了，突然后面全都不通过。

办法：**停下来，等 2–3 小时再跑**。限制会自动恢复。
或者直接降参数：`--speed 1.2 --workers 1`。

**原因 3：上一轮攒的时长不够。**
服务端记的是「累计有效时长」，不是「最后报的位置」。
所以失败后再跑，脚本会先回卷到 0 重新累计，这是正常的，不是 bug。

### 现象：上报返回 HTTP 非 200

| 状态码 | 含义 | 怎么办 |
|---|---|---|
| 202 或正文出现「验证码」 | 触发 9010 风控 | 脚本会停 5 分钟。**你得去浏览器里手动输一次验证码**（手写体，机器认不了） |
| 403 / 401 | 登录态过期 | 重新登录，重跑 `step4_cookies.py` |
| 0（连接异常） | 网络问题 | 脚本会自动重试，持续出现就检查网络 |

### 现象：`取不到视频信息`

`/ananas/status/` 接口没返回 success。通常是：
- 这门课的视频权限有问题（手动在网页里能不能播？）
- 登录态过期

### 进度比预期慢很多

算一下：内容总时长 ÷ 速度 = 理论耗时。
比如 850 分钟内容，1.5 倍速，理论最少约 9.5 小时，实际会更长。
**这个下限是服务器的授权机制决定的，调参也突破不了。**

## 六、跑完之后

**别只看脚本日志，要看服务端。** 日志里的「通过」是服务器返回的即时结果，
但偶尔会滞后。收尾时这样核对：

```
python step6_video.py <课程号> --state
```

显示「已完成 N / M」才是真的完成了。习题也一样，去网页上翻一眼成绩页最稳。

---

## 七、一句话总结这套的东西的脾气

> 服务器不反对你快点看完，但反对你不像人。
> 间隔、速度、并发，三个参数都是「像人」的伪装。
> 任何一个调得太激进，表现都是一样的：**不报错，但就是不给你过**。

所以遇到「明明都成功但没通过」，第一反应不是重试，而是**放慢**。
